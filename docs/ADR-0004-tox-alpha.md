# ADR-0004 — c-toxcore messaging alpha

Date: 2026-10-28. Status: implemented candidate, release gates remain open.

Select c-toxcore 0.2.23 (latest stable release checked against upstream API) for the initial native Android + shared JVM transport. Public bootstrap/TCP relays are allowed under ADR-0003. There is no FG-operated endpoint, mailbox or directory. Do not infer a full product/security audit from this choice.

## Alternatives reviewed

| Engine | Infrastructure / discovery | Content / IP privacy | Platform, files, devices | Decision |
|---|---|---|---|---|
| Tox | Public DHT bootstrap and TCP relays; full public identity address | libsodium transport encryption/authentication; direct peers see IP | Native Android binaries, portable C; file/AV APIs, not yet integrated; no safe native multi-device account model | Initial messaging implementation |
| Tor onion service | Public Tor network; onion address exchange | Onion endpoint authentication and encrypted circuits hide endpoint IP; timing metadata remains | Android needs embedded Tor/service lifecycle; TCP files work, realtime video latency/battery need measurements; account/device model still application work | Evaluate optional privacy transport after core; not implemented |
| Matrix | Public federated homeservers, account tied to server namespace | E2EE available; servers retain events and metadata | Mature multi-device/key backup; attachments and calls require more services; default event persistence conflicts with no offline mailbox | Not selected for online-only core |
| libp2p | DHT, rendezvous/relay peers; independent availability must be established | Noise/TLS secure streams; IP not hidden by default | JVM implementation lacks mature DHT/hole-punching components; files/calls/identity migration are application work | Higher integration burden than Tox |
| WebRTC | Out-of-band signaling plus STUN/TURN for restrictive NAT | DTLS/SRTP; IP exposure unless suitable relay policy | Strong media support and data channels; no identity, contact discovery or account/device lifecycle | Possible future media option, not complete messenger engine |

Battery, Android 15 lifecycle, Windows 10/11, cross-network CGNAT success, media throughput and large-file resumption are **unmeasured**, not inferred from advertised APIs. No engine alone supplies portable multi-device trust and revocation. Public nodes can disappear; ship several independent pinned nodes and expose connection failure.

## Licensing and maintenance

FG Chat is GPL-3.0-or-later to accommodate c-toxcore GPL-3.0 distribution obligations. Commercial distribution is possible subject to the license, corresponding source and notices. This is an engineering choice, not a legal opinion. Tor uses BSD-style licenses; libp2p implementations MIT/Apache-2.0; WebRTC BSD-style; Matrix SDK licenses vary by implementation and must be verified for any selected dependency. No Matrix/Tor/libp2p/WebRTC binary is shipped in this alpha.

0.2.23 fixes GHSA-42vg-9mg3-399f (remote stack overflow in group announce). Upstream has 0.2.24 release candidates with additional handshake hardening; stable 0.2.23 is pinned for reproducibility, and a security review of those changes is a release blocker before wider distribution. Upstream explicitly says the complete protocol has not received independent formal audit. SHA-256 pinning protects against changed downloads, not a compromised upstream/build pipeline.

## Online-only behavior and receipts

No application outbox exists. Send is rejected unless native friend connection and peer session token exchange are ready. No auto resend on reconnect, no message persistence on disk/server. Tox reliable transport can buffer in-flight packets; observed disconnect rotates ephemeral receive tokens and backgrounding reconstructs the engine to discard buffers. During an undetected short network interruption, an already submitted packet may still arrive. Absolute simultaneous-presence guarantees are not achievable on an asynchronous network. UI says “submitted” then “transport received”; this is not a human read receipt. Pending receipt IDs are invalidated across engine restart.

FG1 framing is an application message format inside authenticated Tox encryption, not a new cryptographic protocol. Unrecognized/plain Tox messages are discarded. Text limit 900 UTF-8 bytes prevents exceeding Tox packet size after encoding; it is not a future file-size limit. Incoming UI history bounded to 200 lines/contact; native event queue bounded to 512/iteration, pending requests to 32. Unknown requests require explicit user approval and cannot add friends automatically.

## Identity and invitations

Tox identity is generated by toxcore locally. Savedata, local display name and blocked keys are AES-256-GCM encrypted using Android Keystore and AtomicFile. Corrupt storage/key failure is fail-closed and must not mint a replacement identity. History is memory-only in this alpha. Android backup is disabled. Release screenshots are blocked; debug builds deliberately allow test screenshots. QR scanning reads a selected image with bounded downsampling, no camera permission.

The full 76-hex Tox address is shared by QR/link/copy, and public-key comparison is manual through a trusted channel. **No short-code lookup, expiring/rotating application invitations, independent app root identity, secure account transfer or multi-device authorization is implemented.** Legacy 15-character generator is unused compatibility prototype. Native Tox savedata must never be copied to concurrently active devices.
